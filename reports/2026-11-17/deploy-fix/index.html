02根因：只剥了一个斜杠

CI 构建时 HTML 引用带前缀，而 Vite 产物落在 dist/assets/：

HTML:  /github-daily-trending/assets/index-Cwp7gwZv.css
脚本:  去掉开头一个 "/" → github-daily-trending/assets/index-Cwp7gwZv.css
拼接:  dist/github-daily-trending/assets/index-Cwp7gwZv.css   ← 不存在
实际:  dist/assets/index-Cwp7gwZv.css

本地构建不设这个变量，引用是 ./assets/…，剥完刚好对得上，所以两次交付都没暴露。这个坑从把 inline 步骤接进 npm run build 那一刻就在了。

03修法：按 URL 解析，再加一层兜底

1. 用 URL 语义取路径

new URL(href, 'http://build.local/') 取 pathname，再按 VITE_BASE_PATH 剥出相对 dist 的路径，精确命中；命中不了才按文件名在 dist 内递归兜底，并报错时带上 base 与 dist 信息。

2. 构建后自检 scripts/check-dist.mjs

每次 build 结束检查：无外部 script、无外部样式表、快照在位、dist/data/trending.json 在位。设了 base 也一样跑。

3. 补真实带 base 的构建用例

tests/build-base.test.mjs 在测试里用 VITE_BASE_PATH=/github-daily-trending/ 真跑一次 vite build 再内联断言；tests/inline-build.test.mjs 覆盖带前缀、相对、缺失三种解析。CI 的 npm test 会自动跑到。
